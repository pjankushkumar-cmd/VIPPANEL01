# HACKII Complete Server – v2

## Render settings
- Build command: `npm install`
- Start command: `npm start`
- Environment variables: only `ADMIN_KEY` (minimum 24 characters).
- Runtime: Node.js 22.13+ (Node 26 is supported).
- Persistent Disk: mount at `/opt/render/project/src/data` to preserve `data/hackii.sqlite`.

## Included
- `server.js`: API proxy, authentication, sessions, device limits, expiry, activity logging and SQLite persistence.
- `public/index.html` + `member.js`: simple member login and one upcoming estimate (number + BIG/SMALL), refreshed every 8 seconds.
- `public/admin.html` + `admin.js`: member creation, auto-generated keys, copy key, global/member API keys, block/unblock, ban/unban, expiry extension, device limits, online/offline, login sessions, online duration and activity log.

## Key behavior
- Individual member keys are generated by Admin. Leave the key field blank and press Create, or use Generate.
- Global member key is configured in Global Settings.
- Keys are case-sensitive after trimming surrounding whitespace.
- Member key creation returns the generated key once; copy/save it at creation time.
- Device limit accepts 1 to 100,000. Device binding is browser localStorage based, not hardware attestation.
- Online means a successful authenticated request within 75 seconds. Member page sends heartbeat every 20 seconds. Online time is estimated from authenticated request intervals; closing a browser without logout may leave a session marked online until timeout.
- Activity log records login, logout, device registration and result API reads. It does not inspect private phone contents, IMEI, phone number, or background app usage.

## Result estimate limitations
The server proxies the configured WinGo endpoint. The member page scans up to 10 latest returned records and calculates a deterministic SHA-256-based estimate for the next issue. It displays one digit and BIG/SMALL. SHA-256 cannot predict an external random draw; the estimate is not guaranteed. If the upstream JSON field names or API access rules change, update the parsing functions in `public/member.js` and API URL/header in `server.js`. No fake historical results or fabricated WIN/LOSS records are created.

## Existing database
This release includes schema migration for the new activity/session fields. Keep the Render Persistent Disk mounted at the same path; otherwise a redeploy may use a fresh database and existing member keys will not be present.


## API 403 diagnostic update
The upstream fetch now sends ordinary browser-style Accept, User-Agent, Referer, Origin and X-Requested-With headers. The server logs a short sanitized upstream rejection sample. This can resolve providers that reject bare server fetches, but it cannot override a provider's IP allowlist, access policy, geo restriction, or bot protection. If HTTP 403 persists, use an API endpoint/access method authorized by the provider or ask them to allow the Render outbound IP; do not spoof or evade access controls.
